# 저장소 공개·배포 준비 현황

확인 기준일: **2026-10-20**. 현재 코드·설정과 이 작업에서 확인한 결과를 기준으로 한다.
이미 GitHub 원격 저장소에 코드와 작업 브랜치를 업로드한 상태다. 현재 공개/비공개 설정은
이번 점검에서 확인하지 않았으며, 공개 전환이 아직 필요하다고 가정하지 않는다.

체크 표시는 명시한 범위의 완료를 뜻한다. 로컬 검사 성공, 원격 CI 실행, 이미지 발행,
운영 배포 및 공개 범위 확인은 각각 별도의 증거가 필요하다.

  - 저장소: `https://github.com/xheize/quanyejun`.
  - 이번 코드 수정 브랜치의 로컬·원격 커밋 일치를 확인했다.

  - [`LICENSE`](../LICENSE), [`README.md`](../README.md),

    테스트 및 프런트엔드 애플리케이션 빌드를 실행한다.
  - **Docker 이미지 빌드·발행 단계는 없다.** 애플리케이션 빌드와 구분한다.
- [x] 현재 프런트엔드 변경의 로컬 검증.
  - 타입 검사, lint, 빌드 및 테스트 17개가 통과했다.
  - 로컬 API·Chrome UI 검증 범위와 남은 항목은 [`DESIGN.md`](../DESIGN.md)에 기록했다.
- [x] 민감 파일 제외 규칙 보강.
  - [`.gitignore`](../.gitignore)에 환경변수 파일, 개인키, 관리자 설정, DB 덤프·백업,
    런타임 데이터 등의 제외 규칙이 있다.
  - 루트와 프런트엔드의 `.dockerignore`에 환경변수 파일·키·로컬 산출물 등의 제외 규칙이 있다.
  - 규칙의 존재를 확인한 것으로, 모든 민감 파일의 제외나 과거 이력의 안전성을 보증하지 않는다.
- [x] 프런트엔드와 Go 엔진의 Dockerfile 및 로컬 Compose 구성.
  - 프런트엔드 빌드 컨텍스트는 `frontend/`, 엔진은 저장소 루트다.
  - 이는 실행 구성의 존재를 뜻하며 운영 배포 완료를 뜻하지 않는다.

## 추가 확인이 필요한 항목

- [ ] 원격 저장소의 현재 공개 범위와 공개 대상 브랜치·태그를 확인한다.
- [ ] 공개 대상 이력과 신규 변경의 비밀정보 검사 결과를 최신 기준으로 확인한다.
  - 이번 문서 점검에서는 전체 이력 전문 검사를 다시 수행하지 않았다.
  - 과거 특정 커밋 범위의 검사 결과를 현재 모든 브랜치·태그로 확대 해석하지 않는다.
  - 실제 자격 증명이 발견되면 폐기·재발급과 필요한 이력 정리를 별도로 진행한다.
  - 보고서·로그에는 민감값 원문을 남기지 않는다.
- [ ] 이름·실제 서비스 주소·내부 주소·커밋 작성자 정보의 공개 범위를 확인한다.
  - 점검 시 로컬 Git 이메일 설정과 최신 코드 커밋의 작성자 이메일은 `noreply` 형식이 아니었다.
  - 이메일 원문은 기록하지 않는다. 변경 또는 과거 이력 재작성 여부는 별도 결정한다.
- [ ] 운영 자격 증명과 개발 예제 설정이 분리돼 있는지 운영 환경에서 확인한다.
  - [`compose.yaml`](../compose.yaml)의 DB 계정·비밀번호는 로컬 개발 예제 값이다.
  - 운영 비밀값은 비밀 설정으로 관리하고 `NEXT_PUBLIC_*`에는 넣지 않는다.
- [ ] Git 추적 파일과 실제 Docker 빌드 컨텍스트의 민감 파일 포함 여부를 확인한다.
  - ignore 규칙은 이미 추적된 파일이나 과거 커밋을 제거하지 않는다.
  - DB 덤프·백업·키·세션 설정을 확인하되 마이그레이션과 공개용 예제는 유지한다.
- [ ] 원격 Woodpecker 활성화·실행 결과와 CI·배포 자격 증명의 권한을 확인한다.
  - 로컬 테스트 통과나 파이프라인 파일 존재만으로 원격 CI 성공을 판단하지 않는다.
- [ ] 코드·이미지·자산의 출처와 사용 조건, 이슈·PR·로그·아티팩트·릴리스의 공개 내용을 확인한다.

## 현재 CI 범위와 별도 검토 항목

현재 방침은 **프런트엔드만 CI에서 검사**하는 것이다. 백엔드 CI는 필수 미완료 작업으로
취급하지 않는다. 다음 항목은 필요성과 운영 비용을 검토한 뒤 범위를 별도로 결정한다.

- 비밀정보 검사 자동화와 의존성·이미지 취약점 검사 및 업데이트 알림.
- 프런트엔드 Docker 이미지 빌드·발행.
- 백엔드 테스트·race 검사·PostgreSQL 통합 테스트·컨테이너 빌드의 CI 편입.

현재 파이프라인에는 위 단계가 없다. 백엔드의 로컬 테스트·빌드 결과는 원격 CI와 구분해서 기록한다.
